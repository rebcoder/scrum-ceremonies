Three ceremonies

Everything a sprint needs to talk about itself.

Each tool is its own room. Open one, share the code, and the ceremony runs in real time for everyone who joins.

Planning Poker

Estimate backlog items together. Everyone picks a card, the host reveals, and the room sees the spread, the average and whether it reached consensus.

  • Fibonacci deck, 1 to 20, plus a coffee-break card
  • Reveal and clear rounds as many times as you need
  • Live participant list with who has voted
Start Poker

Sprint Retrospective

Went Well, Improve, Improvement Actions. Live cards from everyone, dot-voting to surface what matters, and a board you can take away.

  • Vote budget per person, sort by votes, search
  • Built-in timer for timeboxed discussion
  • Export the whole board to PDF
Start Retro

Team Mood Check

An anonymous pulse before or after the sprint. Quick Pulse is one tap; Scrum Pulse adds questions on blockers and confidence.

  • Answers are never linked to names
  • Comments appear only once three or more people answer
  • Host reveals the distribution when everyone is in

How it works

From link to ceremony in under a minute.

  1. Create a room

    Type a name and pick a tool. You get an 8-character room code and a link you can paste anywhere.

  2. Share the code

    Teammates open the link on any device and type a name. Nobody signs up, nobody installs anything.

  3. Run the ceremony

    Vote, post, reveal. Every change reaches everyone in the room instantly. Export a PDF if you want to keep the result.

8h

Rooms live in Redis for eight hours, then they are gone. Nothing is archived.

10

Seats per room. Enough for a Scrum team, small enough to stay a conversation.

0

Accounts, trackers, ad scripts or third-party calls. The pages talk only to your own server.

MIT

Licensed for anyone to run, change and ship. One JVM and one Redis is the whole stack.

Self-host

Your team's data on your own box.

  • Java 17 and Spring Boot behind, plain HTML, CSS and JavaScript in front. No database, no build step for the pages.
  • Redis is the only dependency. Room state, presence and rate limits are Lua scripts on one instance.
  • Docker Compose brings up the API; serve the pages from any static host or the same reverse proxy.
